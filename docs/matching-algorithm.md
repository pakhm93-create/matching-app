# 매칭 알고리즘 · 배급 · 수익화 설계

## 한 줄 요약
**걸러내고(필터) → 점수 매기고(유사도) → 서로 만족하는지 확인하고(양방향)
→ 아껴서 내보낸다(배급).**

마지막 "배급"이 이 앱의 수익 모델과 직결된다. 상위 N명을 한 번에 다 보여주면
사용자는 하루 만에 다 소비하고 떠난다.

---

## 0단계: 우선순위 TOP 3 — 설문 시작 전

설문에 들어가기 전 한 화면에서 **"절대 양보할 수 없는 조건 3개"**를 고르게 한다.

> 선택지: 나이 · 지역 · 흡연 · 음주 · 종교 · 정치 성향 · 결혼 의향 ·
> 자녀 계획 · 직업군 · 키 · 학력 · 타투 · 반려동물

**고른 3개가 두 가지 역할을 동시에 한다.**

| 역할 | 작동 방식 |
|---|---|
| ① 하드 필터 | 이 3개 조건에 맞지 않으면 **후보에서 아예 제외** |
| ② 가중치 증폭 | 관련 문항의 유사도 가중치를 **5배**로 올림 |

**왜 3개로 제한하는가**
- 문항마다 중요도를 물으면 응답 부담이 2배가 되어 이탈한다
- 조건을 무제한으로 걸게 하면 후보가 0명이 된다.
  3개 제한은 사용자가 스스로 우선순위를 정리하게 만드는 장치이기도 하다
- 나머지 조건들은 버려지지 않는다. **하드 필터가 아닌 점수(유사도)로 반영**된다

---

## 1단계: 하드 필터 — 통과 아니면 탈락

1. **항상 적용**: 찾는 성별이 서로 맞는가
2. **사용자가 고른 TOP 3 조건**을 서로 만족하는가
   (양방향 — 내 조건도 맞고, 상대의 조건에도 내가 맞아야 함)

> **이 순서가 중요한 이유**: 유사도부터 계산하면 "취향은 완벽한데 담배를
> 죽어도 못 참는 사람"이 1순위로 추천되는 사고가 난다. 필터가 먼저다.

## 2단계: 문항별 유사도 계산 (0 ~ 1)

| 형식 | 계산법 | 예시 |
|---|---|---|
| `scale` (1~5) | `1 - |내 답 - 상대 답| / 4` | 4 vs 5 → **0.75** |
| `choice` | 같으면 1, 다르면 0 | 둘 다 무교 → **1.0** |
| `choice` (유사 인정) | 부분 점수표 사용 | 개신교 vs 천주교 → **0.5** |
| `multi` | 겹치는 개수 ÷ 전체 개수 | 3개 겹침 / 총 8개 → **0.375** |

## 3단계: 가중치

```
문항 가중치 = 섹션 가중치 × (TOP 3에 포함되면 5, 아니면 1)
```

| 섹션 | 가중치 |
|---|---|
| C 가치관 | 0.35 |
| D 관계 스타일 | 0.25 |
| E 생활 습관 | 0.15 |
| F 성격 | 0.15 |
| G 취향 | 0.10 |

## 4단계: 양방향 점수 — 한쪽 짝사랑 방지

```
S(A→B) = Σ(A의 문항 가중치 × 유사도) ÷ Σ(A의 문항 가중치)
S(B→A) = Σ(B의 문항 가중치 × 유사도) ÷ Σ(B의 문항 가중치)

최종 궁합 = √( S(A→B) × S(B→A) ) × 100
```

**왜 산술평균이 아니라 기하평균(√곱)인가**
한쪽 0.9, 다른 쪽 0.3인 경우
- 산술평균 → 0.60 (그럴듯해 보임 ❌)
- 기하평균 → 0.52 (한쪽이 낮으면 확실히 끌어내림 ✅)

매칭은 **양쪽이 다 좋아야** 성립한다.

## 5단계: 배급 — "5일장" 모델

계산된 상위 후보를 **한 번에 다 보여주지 않는다.** 정해진 주기에 맞춰 내보낸다.

### 기본 리듬
- **주 1회, 정해진 요일·시각**에 "이번 주 인연 도착" 푸시 알림
- 무료 사용자: **1명** 공개
- 유효기간을 둔다 (예: 7일). 기간이 지나면 사라진다 → 지금 행동할 이유를 만든다

### 왜 이 방식인가
| 효과 | 설명 |
|---|---|
| 희소성 | 하루에 수십 명 스와이프하는 앱과 정반대 포지션. "아무나"가 아니라는 인상 |
| 재방문 습관 | 매주 같은 시각 알림 = 앱을 여는 리듬이 생김 |
| 결제 동기 | 마음에 드는데 기다려야 할 때 결제가 일어난다 |
| 진지함 필터 | 가볍게 쓰는 사용자가 자연스럽게 걸러짐 |

### ⚠️ 균형 잡을 것
주 1회 1명은 **초기 사용자가 적을 때 위험**하다. 조건 맞는 상대가 아예 안 나올 수 있다.
- 후보가 없는 주에는 "이번 주는 인연이 없었어요" 대신 **조건 완화 제안**을 보낸다
- 초기에는 주 2~3명으로 시작해 사용자가 늘면 조이는 방향을 검토

## 6단계: 수익화 — 매칭 토큰

**토큰을 구매해 소비하는 방식.** 구독보다 초기 진입 장벽이 낮다.

| 토큰 사용처 | 설명 | 우선순위 |
|---|---|---|
| **먼저 연락 보내기** | 매칭 상대에게 메시지를 거는 순간 | ⭐ 핵심 |
| **추가 인연 열람** | 다음 주까지 안 기다리고 지금 더 받기 | ⭐ 핵심 |
| 궁합 상세 리포트 | 어느 항목이 왜 맞는지 전체 분석 | 보조 |
| 관심 표시 확인 | 나를 좋아한 사람이 있는지 미리 보기 | 보조 |
| 프로필 다시 보기 | 유효기간이 지나 사라진 인연 복구 | 보조 |

> **설계 원칙**: 돈을 내야 매칭이 "더 정확해지는" 구조는 만들지 않는다.
> 정확도는 무료로 동일하게 주고, **속도와 양**에만 과금한다.
> 정확도에 과금하면 매칭 품질에 대한 신뢰가 무너진다.

---

## 7단계: 결과 표시

- 궁합 %와 함께 **"어디가 잘 맞는지"를 반드시 같이 보여준다**
  → `궁합 87% · 가치관과 연락 스타일이 특히 잘 맞아요`
  → 숫자만 보여주면 신뢰하지 않는다. 근거가 설득력을 만든다
- **안 맞는 항목 1~2개도 솔직히 표시**하면 오히려 신뢰도가 올라간다

---

## 시제품(MVP) 단계에서 검증할 것

1. 가짜 사용자 50명을 생성해 매칭을 돌린다
2. **일부러 극단적인 프로필을 심는다**
   - 모든 항목이 정반대인 두 사람 → 궁합 20% 아래로 나오는가
   - 거의 동일한 두 사람 → 90% 이상 나오는가
3. TOP 3 필터를 켰을 때 후보가 과하게 줄지 않는지 확인
4. 결과가 납득 안 되면 **섹션 가중치를 조정** (코드 한 줄 수정으로 가능하게 설계)

## 나중에 다룰 것 (MVP 이후)

- **데이트 코스 추천** — 매칭된 두 사람의 취미·취향 데이터를 이미 갖고 있으므로,
  "어디서 만나 무엇을 하면 좋을지"를 추천할 수 있다. 이 앱만의 강력한 차별점이 될 수 있음
- **"비슷한 게 항상 좋은가"** — 가치관·생활습관은 비슷할수록 좋다는 근거가 있으나,
  성격(특히 외향성)은 적당히 다른 쪽이 나을 수 있다. 실사용 데이터로 튜닝
- **성능** — 수천 명까지는 전원 비교해도 무방. 수만 명 넘어가면 지역·나이로 1차 축소
