# 매칭 알고리즘 설계

## 한 줄 요약
**걸러내고(필터) → 점수 매기고(유사도) → 서로 만족하는지 확인한다(양방향).**

---

## 1단계: 딜브레이커 필터 — 통과 아니면 탈락

점수를 계산하기 전에 후보를 쳐낸다. 여기서 걸리면 **궁합이 99%여도 보여주지 않는다.**

- 찾는 성별이 서로 맞는가
- 나이가 서로가 지정한 범위 안에 드는가
- 지역 조건을 만족하는가
- 흡연/음주/결혼 의향/자녀 계획/반려동물이 서로 허용 범위 안인가

> **이 순서가 중요한 이유**: 유사도부터 계산하면 "취향은 완벽한데 담배를
> 죽어도 못 참는 사람"이 1순위로 추천되는 사고가 난다. 필터가 먼저다.

## 2단계: 문항별 유사도 계산 (0 ~ 1)

| 형식 | 계산법 | 예시 |
|---|---|---|
| `scale` (1~5) | `1 - |내 답 - 상대 답| / 4` | 4 vs 5 → `1 - 1/4` = **0.75** |
| `choice` | 같으면 1, 다르면 0 | 둘 다 무교 → **1.0** |
| `choice` (유사 인정) | 부분 점수표 사용 | 개신교 vs 천주교 → **0.5** |
| `multi` | 겹치는 개수 ÷ 전체 개수 | 취미 3개 겹침/총 8개 → **0.375** |

## 3단계: 가중치 — 이 앱의 핵심

문항 하나의 최종 무게는 **두 가지를 곱해서** 정한다.

```
문항 가중치 = 섹션 가중치 × 내가 매긴 중요도
```

**섹션 가중치** (관계 지속성 예측력 순)

| 섹션 | 가중치 |
|---|---|
| C 가치관 | 0.35 |
| D 관계 스타일 | 0.25 |
| E 생활 습관 | 0.15 |
| F 성격 | 0.15 |
| G 취향 | 0.10 |

**개인 중요도** (사용자가 문항마다 직접 선택)

| 선택 | 값 |
|---|---|
| 상관없음 | 0 |
| 조금 중요 | 1 |
| 중요 | 3 |
| 매우 중요 | 10 |

> 간격을 1·3·10으로 크게 벌린 이유: "매우 중요"라고 답한 소수 문항이
> "상관없음" 수십 개에 묻히면 안 되기 때문. 사용자가 진짜 신경 쓰는 항목이
> 결과를 지배해야 체감 정확도가 올라간다.

## 4단계: 양방향 점수 — 한쪽 짝사랑 방지

A가 B에게 만족하는 정도와, B가 A에게 만족하는 정도를 **따로** 계산한다.

```
S(A→B) = Σ(A의 문항 가중치 × 유사도) ÷ Σ(A의 문항 가중치)
S(B→A) = Σ(B의 문항 가중치 × 유사도) ÷ Σ(B의 문항 가중치)

최종 궁합 = √( S(A→B) × S(B→A) ) × 100
```

**왜 평균이 아니라 기하평균(√곱)인가**
한쪽이 0.9, 다른 쪽이 0.3인 경우
- 산술평균 → 0.60 (그럴듯해 보임 ❌)
- 기하평균 → 0.52 (한쪽이 낮으면 확실히 끌어내림 ✅)

매칭은 **양쪽이 다 좋아야** 성립한다. 기하평균이 이 성질을 정확히 표현한다.

## 5단계: 결과 표시

- 상위 N명을 "오늘의 추천"으로 하루 몇 명씩만 노출 (한 번에 다 보여주면 소비되고 끝)
- 궁합 %와 함께 **"어디가 잘 맞는지"를 반드시 같이 보여준다**
  → 예: `궁합 87% · 가치관과 연락 스타일이 특히 잘 맞아요`
  → 숫자만 보여주면 신뢰하지 않는다. 근거가 설득력을 만든다
- 반대로 **안 맞는 항목 1~2개도 솔직히 표시**하면 신뢰도가 올라간다

---

## 시제품 단계에서 검증할 것

1. 가짜 사용자 50명을 생성해 매칭을 돌린다
2. **일부러 극단적인 프로필을 심는다** — 예: 모든 항목이 정반대인 두 사람
   → 궁합이 20% 아래로 나오는지 확인
   → 거의 동일한 두 사람은 90% 이상 나오는지 확인
3. 결과가 납득이 안 되면 **섹션 가중치를 조정**한다 (코드 한 줄 수정으로 가능하게 설계)

## 나중에 다룰 문제 (지금은 신경 쓰지 말 것)

- **"비슷한 게 항상 좋은가"** — 가치관·생활습관은 비슷할수록 좋다는 근거가 있지만,
  성격(특히 외향성)은 적당히 다른 쪽이 나을 수 있다. 실제 사용 데이터가 쌓이면 튜닝
- **성능** — 사용자가 수천 명까지는 전원 비교해도 문제없다.
  수만 명이 넘어가면 지역·나이로 1차 축소 후 계산
- **후보 없음** — 조건이 너무 빡빡해 결과가 0명이면
  "지역 조건을 넓혀볼까요?" 식으로 완화를 제안
